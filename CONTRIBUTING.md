# Contributing to DuckHaven

Thanks for your interest in contributing. The full guide lives on the docs site:
[Contributing](https://tamasmrtn.github.io/duckhaven/developer/contributing/), with
[Local development](https://tamasmrtn.github.io/duckhaven/developer/development/) for setting up the stack and
[Testing](https://tamasmrtn.github.io/duckhaven/developer/testing/) for the test suite.

The short version:

- **Bugs, features and questions:** open an [issue](https://github.com/tamasmrtn/duckhaven/issues/new/choose) using
  one of the forms. For a large change, agree on the approach in an issue before writing the code.
- **Security vulnerabilities:** never in a public issue. Follow [SECURITY.md](SECURITY.md).
- **Pull requests:** branch from `main` with a type prefix (`feat/`, `fix/`, `chore/`, `docs/`, `refactor/`, `test/`),
  write [Conventional Commits](https://www.conventionalcommits.org/), and include tests and docs for every behavior
  change.
- **Sign off every commit** (`git commit -s`) under the
  [Developer Certificate of Origin](https://developercertificate.org/). CI checks it.
- **AI tools are allowed.** You remain the author: understand and be able to explain every line, and say in the pull
  request when an AI tool wrote a substantial part of it.

Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).
